# **Comparison of Sorting Algorithms & When to Use Which**

## *Introduction*
We covered several sorting algorithms, each with different strengths. Choosing the right one depends on input size, whether the data is nearly sorted, memory limits, and whether stability matters.

### Comparison Table

| Algorithm       | Best Time  | Average Time | Worst Time | Space    | Stable? | In Place? |
| --------------- | ---------- | ------------ | ---------- | -------- | ------- | --------- |
| Bubble Sort     | O(n)       | O(n²)        | O(n²)      | O(1)     | Yes     | Yes       |
| Selection Sort  | O(n²)      | O(n²)        | O(n²)      | O(1)     | No      | Yes       |
| Insertion Sort  | O(n)       | O(n²)        | O(n²)      | O(1)     | Yes     | Yes       |
| Merge Sort      | O(n log n) | O(n log n)   | O(n log n) | O(n)     | Yes     | No        |
| Quick Sort      | O(n log n) | O(n log n)   | O(n²)      | O(log n) | No      | Yes       |
| JS `sort()` (TimSort) | O(n) | O(n log n)   | O(n log n) | O(n)     | Yes     | No        |

### When to Use Which Sort
1. **Insertion Sort** — small arrays (n ≲ 50) or nearly sorted data; also used inside hybrid sorts like TimSort.
2. **Bubble Sort** — mainly for learning; the swapped flag makes it decent on nearly sorted input, but insertion sort does that better.
3. **Selection Sort** — when the number of **writes/swaps** must be minimized (e.g. flash memory); otherwise rarely the best pick.
4. **Merge Sort** — when you need a **stable** sort and guaranteed O(n log n), or when sorting linked lists / data that doesn't fit in memory (external sorting).
5. **Quick Sort** — general-purpose, fastest in practice for arrays in memory when stability is not needed; use a random pivot to avoid the worst case.
6. **Built-in `Array.prototype.sort()`** — the default choice in real JavaScript code: O(n log n), stable, and highly optimized. Write your own sorts to learn, ship the built-in one.

### Key Points to Remember
1. No comparison-based sort can beat **O(n log n)** in the average/worst case — that is a proven lower bound.
2. O(n²) sorts are fine for tiny inputs; O(n log n) sorts win as data grows.
3. Stability + guaranteed O(n log n) → Merge Sort. Speed + low memory → Quick Sort.

# **Conclusion**
Each sorting algorithm trades time, space and stability differently. For real JavaScript work, the stable O(n log n) built-in `sort()` is almost always the right answer, while merge sort and quick sort remain essential to know for interviews and specialized situations.
