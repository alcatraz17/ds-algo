# **Intersection and Union of Two Sorted Arrays**

## *Introduction*
When two arrays are already **sorted**, we can find their intersection (common elements) and union (all distinct elements) efficiently using the same **two-pointer merge logic** as merge sort — in O(m + n) time, instead of O(m × n) with nested loops.

### Intersection (Common Elements)
Walk both arrays with pointers `i` and `j` (see `07.intersectionOfTwoArrays.js`):

1. If `arr1[i] < arr2[j]` → move `i` forward.
2. If `arr1[i] > arr2[j]` → move `j` forward.
3. If equal → record the element, move both.
4. Skip duplicates so each common value is printed once.

```javascript
if (i > 0 && arr1[i - 1] === arr1[i]) { i++; continue; } // skip duplicates
if (arr1[i] < arr2[j]) i++;
else if (arr1[i] > arr2[j]) j++;
else { arr[k++] = arr1[i]; i++; j++; }
```

Example: `[1,2,3,4,5,6,7,8]` ∩ `[2,4,6,8]` → `[2,4,6,8]`

### Union (All Distinct Elements)
Same two pointers, but every element is added, and when both are equal only **one** copy is taken (see `08.unionOfArrays.js`):

1. If `a[i] === b[j]` → add once, advance both.
2. If `a[i] < b[j]` → add `a[i]`, advance `i`.
3. Else → add `b[j]`, advance `j`.
4. Copy whatever remains from either array.

Example: `[1,2,3]` ∪ `[2,4]` → `[1,2,3,4]`

### Complexity
1. **Time**: O(m + n) — each element is visited at most once.
2. **Space**: O(m + n) for the result array (or O(1) extra if only printing).

### Key Points to Remember
1. These techniques only work because the inputs are sorted.
2. The duplicate-skip check (`arr[i-1] === arr[i]`) is what keeps results distinct.
3. Hash sets are an alternative (average O(m + n)) but lose the sorted order and use extra memory.

# **Conclusion**
Using the merge pattern of merge sort, intersection and union of two sorted arrays are solved in linear O(m + n) time with two pointers — a big improvement over the naive O(m × n) approach.
