# **Merge Sort**

## *Introduction*
Merge sort is a **divide and conquer** algorithm. It splits the array into two halves, recursively sorts each half, and then **merges** the two sorted halves into one sorted array. Unlike the O(n²) simple sorts, merge sort guarantees O(n log n) time.

### Merging Two Sorted Subarrays
The heart of merge sort is the merge step: walk two sorted arrays with two pointers and always take the smaller element. See `06.mergeTwoSortedArrays.js`:

```javascript
function merge(arr1, arr2) {
  let arr3 = [];
  let i = 0, j = 0, k = 0;

  while (i < arr1.length && j < arr2.length) {
    if (arr1[i] < arr2[j]) arr3[k++] = arr1[i++];
    else arr3[k++] = arr2[j++];
  }
  while (i < arr1.length) arr3[k++] = arr1[i++];
  while (j < arr2.length) arr3[k++] = arr2[j++];

  return arr3;
}
```

Merging two arrays of total size n takes **O(n)** time and **O(n)** extra space.

### Merge Sort Itself
See `05.mergeSort.js`:

```javascript
function mergeSort(arr) {
  if (arr.length <= 1) return arr;

  let mid = Math.floor(arr.length / 2);
  let left = mergeSort(arr.slice(0, mid));
  let right = mergeSort(arr.slice(mid));

  return merge(left, right);
}
```

### Complexity
1. **Time**: O(n log n) in best, average and worst case — log n levels of splitting, O(n) merge work per level.
2. **Space**: O(n) — extra arrays are created during merging.
3. **Stable**: Yes — equal elements keep their order when merge prefers the left element on ties.
4. **Not in place**: needs auxiliary memory, which is its main drawback.

### Key Points to Remember
1. Predictable O(n log n) — no bad worst case like quick sort.
2. Best choice when stability is required or when sorting linked lists (O(1) extra space there).
3. The same two-pointer merge idea powers intersection, union and inversion counting.

# **Conclusion**
Merge sort divides the array in half recursively and merges the sorted halves back together in O(n) per level, giving O(n log n) time in all cases. It is stable and reliable but uses O(n) extra space.
