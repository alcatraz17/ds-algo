# **Quick Sort**

## *Introduction*
Quick sort is a **divide and conquer** algorithm. It picks a **pivot** element and **partitions** the array so that elements smaller than the pivot are on its left and larger ones on its right, then recursively sorts both sides. In the average case it is the fastest general-purpose sort, but unlike merge sort it has an O(n²) worst case.

### Lomuto Partition
Chooses the **last element** as the pivot and maintains an index `i` of the last element smaller than the pivot (see `10.lomutoPartition.js`):

```javascript
function lomutoPartition(arr, l, h) {
  let pivot = arr[h];
  let i = l - 1;
  for (let j = l; j <= h - 1; j++) {
    if (arr[j] < pivot) {
      i++;
      [arr[i], arr[j]] = [arr[j], arr[i]];
    }
  }
  [arr[i + 1], arr[h]] = [arr[h], arr[i + 1]];
  return i + 1; // final pivot position
}
```

1. Single left-to-right scan — simple to understand and implement.
2. Does **more swaps** than Hoare's, and performs poorly on already sorted input.

### Hoare's Partition
Uses **two pointers** moving toward each other: `i` moves right past elements `< pivot`, `j` moves left past elements `> pivot`; if `i < j`, swap them and continue.

```javascript
function hoarePartition(arr, l, h) {
  let pivot = arr[l];
  let i = l - 1, j = h + 1;
  while (true) {
    do { i++; } while (arr[i] < pivot);
    do { j--; } while (arr[j] > pivot);
    if (i >= j) return j;
    [arr[i], arr[j]] = [arr[j], arr[i]];
  }
}
```

1. About **3× fewer swaps** on average than Lomuto.
2. The returned index is **not** the pivot's final position — recursion is `qSort(l, j)` and `qSort(j + 1, h)`.

### Complexity
1. **Time (best/avg)**: O(n log n) — balanced partitions.
2. **Time (worst)**: O(n²) — already sorted array with a fixed pivot choice (first/last element).
3. **Space**: O(log n) recursion stack on average, O(n) worst case.
4. **Stable**: No. **In place**: Yes (unlike merge sort).

### Key Points to Remember
1. Choosing a **random pivot** makes the O(n²) worst case very unlikely.
2. Quick sort is usually faster than merge sort in practice thanks to better cache behavior and no extra array allocation.
3. Worst case for both Lomuto and Hoare: sorted input with corner element as pivot.

# **Conclusion**
Quick sort partitions the array around a pivot and recursively sorts both sides, giving O(n log n) average time with O(1) extra space. Lomuto's partition is simpler; Hoare's does fewer swaps. Its O(n²) worst case is avoided in practice with random pivots.
