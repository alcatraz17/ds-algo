# **Count Inversions in an Array**

## *Introduction*
An **inversion** is a pair of indices `(i, j)` such that `i < j` but `arr[i] > arr[j]` — two elements that are out of order. The inversion count tells how far the array is from being sorted:

1. A sorted array has **0** inversions.
2. A reverse-sorted array has the maximum: **n(n−1)/2** inversions.

Example: `[2, 4, 1, 3, 5]` has 3 inversions → `(2,1)`, `(4,1)`, `(4,3)`.

### Naive Approach
Check every pair with two loops. Simple but **O(n²)** time — too slow for large arrays. (This is kept as a commented-out solution in `articles/09.inverstionOfArray.js`.)

### Efficient Approach: Modified Merge Sort
Key idea: while merging two sorted halves, whenever we take an element from the **right** half before finishing the left half, that element forms an inversion with **every remaining element** in the left half — so we add `left.length - i` to the count.

```javascript
while (i < left.length && j < right.length) {
  if (left[i] <= right[j]) {
    arr[k++] = left[i++];
  } else {
    arr[k++] = right[j++];
    res += left.length - i; // all remaining left elements are inversions
  }
}
```

The recursion counts inversions in the left half, the right half, and the split (cross) inversions during merge — see `articles/09.inverstionOfArray.js`:

```javascript
function countInversion(arr, l, r) {
  let res = 0;
  if (l < r) {
    let m = Math.floor((l + r) / 2);
    res += countInversion(arr, l, m);
    res += countInversion(arr, m + 1, r);
    res += cMerge(arr, l, m, r);
  }
  return res;
}
```

### Complexity
1. **Time**: O(n log n) — same as merge sort.
2. **Space**: O(n) — temporary arrays during merge.

### Key Points to Remember
1. `left[i] <= right[j]` (not `<`) keeps the count correct for equal elements — equal pairs are not inversions.
2. One merge step can count many inversions at once (`left.length - i`), which is why this beats the naive pair-by-pair check.
3. Note: this process **sorts the array** as a side effect.

# **Conclusion**
Counting inversions with a modified merge sort reduces the work from O(n²) to O(n log n) by counting whole groups of inversions (`left.length - i`) during each merge step.
