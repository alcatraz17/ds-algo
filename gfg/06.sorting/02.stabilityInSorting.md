# **Stability in Sorting**

## *Introduction*
A sorting algorithm is called **stable** if two elements with equal keys keep the same relative order in the sorted output as they had in the input. Stability does not matter for plain numbers, but it matters a lot when sorting objects (records) by one field.

### Example
Imagine students sorted by marks. Two students both scored 80:

```javascript
let students = [
  { name: "Aman", marks: 80 },
  { name: "Riya", marks: 95 },
  { name: "Neha", marks: 80 },
];

students.sort((a, b) => a.marks - b.marks);
// Stable sort keeps Aman before Neha (same order as input)
```

### Why Does Stability Matter?
1. **Multi-level sorting**: Sort by one key, then by another — a stable sort preserves the previous ordering within equal groups.
2. **Predictable output**: Equal elements stay in their original (e.g. insertion) order, which is often meaningful.

### Stable vs Unstable Algorithms
1. **Stable**: Bubble Sort, Insertion Sort, Merge Sort, Counting Sort, built-in `Array.prototype.sort()` (in modern JS engines, ES2019+).
2. **Unstable**: Selection Sort, Quick Sort, Heap Sort.

### Key Points to Remember
1. An unstable sort can sometimes be made stable by adding the original index as a tie-breaker in the comparator.
2. Since ES2019, JavaScript's built-in `sort()` is **guaranteed to be stable**.
3. Stability only matters when elements can compare equal and their original order carries meaning.

# **Conclusion**
Stability means equal elements keep their original relative order after sorting. Merge sort, bubble sort and insertion sort are stable, while selection sort and quick sort are not. JavaScript's built-in sort is stable, which makes multi-key sorting easy and reliable.
