# **Second Largest Element in an Array**

## *Introduction*
Now we want the second biggest value. A naive way is to find the largest first and then scan again ignoring it — that takes two passes. We can do it in one pass by tracking two variables at once.

## *Idea*
1. **Keep two variables**: `largest` and `secondLargest`.
2. **On each element**:
   - If it beats `largest`, the old largest becomes the second largest, and this element becomes the new largest.
   - Else if it beats `secondLargest` (and is not equal to `largest`), update the second largest.
3. **Return `secondLargest`** at the end.

### Code (from 02.secondLargest.js)

```JavaScript
function findSecondLargest(arr) {
  let largest = arr[0];
  let secondLargest = 0;

  for (let i = 0; i < arr.length; i++) {
    if (arr[i] > largest) {
      secondLargest = largest;
      largest = arr[i];
    } else if (arr[i] > secondLargest && arr[i] !== largest) {
      secondLargest = arr[i];
    }
  }

  return secondLargest;
}
```

The same one-pass pattern, returning both values, is also used in `../problems/04.maxAndSecondMax.js`.

## *Analysis*
1. **Time Complexity: O(n)** — single traversal, better than the two-pass naive approach (still O(n) but with double the comparisons).
2. **Space Complexity: O(1)** — only two extra variables.

## *Key Points to Remember*
1. **Handle duplicates**: the check `arr[i] !== largest` stops a repeated maximum from becoming its own "second largest".
2. **Edge case**: if all elements are equal (e.g. `[5, 5, 5]`), there is no second largest — interviews expect you to return something like -1 or handle it explicitly.
3. **Sorting is overkill**: sorting takes O(n log n) when a single O(n) pass solves it.

# **Conclusion**
The second largest element can be found in one pass by maintaining the largest and second largest values together and updating them as you scan. This gives O(n) time and O(1) space without sorting.
