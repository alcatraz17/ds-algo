# **Move Zeros to End**

## *Introduction*
Given an array containing some zeros, move all zeros to the end while keeping the relative order of the non-zero elements. Example: `[1, 0, 2, 0, 3]` becomes `[1, 2, 3, 0, 0]`.

## *Idea*
1. **Keep a counter `count`** marking the position where the next non-zero element should go.
2. **Scan the array**: every time you see a non-zero element, swap it with the element at `count` and increment `count`.
3. **At the end**, all non-zeros are at the front in original order, and zeros have been pushed behind them.

### Code (from 05.zeroShift.js)

```JavaScript
function zeroShift(arr) {
  let count = 0;
  for (let i = 0; i < arr.length; i++) {
    if (arr[i] !== 0) {
      [arr[i], arr[count]] = [arr[count], arr[i]];
      count++;
    }
  }

  return arr;
}
```

## *Analysis*
1. **Time Complexity: O(n)** — one traversal of the array.
2. **Space Complexity: O(1)** — in-place swaps, no extra array.
3. **Naive alternative**: first pass to count zeros / copy non-zeros into a temp array, then fill the tail with zeros — still O(n) time but O(n) extra space.

## *Key Points to Remember*
1. **Same slow/fast pointer pattern** as removing duplicates: `i` reads, `count` writes.
2. **Order is preserved** because non-zeros are written in the order they are read.
3. **When `i === count` the swap is a no-op**, so leading non-zeros stay untouched.

# **Conclusion**
Moving zeros to the end is a single O(n) pass with O(1) space using a write-pointer for the next non-zero element. It is the same compaction pattern used in the remove-duplicates problem.
