# **Remove Duplicates from a Sorted Array**

## *Introduction*
In a **sorted** array, all duplicates sit next to each other. The goal is to keep only one copy of each value, in place, and return the new logical size. The extra elements beyond that size do not matter.

## *Idea*
1. **The first element is always kept.**
2. **Scan from the second element**: whenever a value differs from the last kept one, place it at the next free position and move that position forward.
3. **Return the count of kept elements** — the array up to that index holds the unique values.

### Code (from articles/06.removeDup.js)

```JavaScript
function remDup(arr) {
  let temp = [arr[0]];
  let res = 1;

  for (let i = 1; i < arr.length; i++) {
    if (temp[res - 1] !== arr[i]) {
      temp[res] = arr[i];
      res++;
    }
  }

  for (let i = 0; i < res; i++) {
    arr[i] = temp[i];
  }

  return res;   // new size; arr.slice(0, res) has the unique values
}
```

## *Analysis*
1. **Time Complexity: O(n)** — single pass over the array.
2. **Space Complexity: O(n)** here because of the `temp` array; a fully in-place version writes directly into `arr[res]` and needs only **O(1)** space.
3. **Why sorted matters**: duplicates are adjacent, so comparing only with the last kept value is enough. For unsorted arrays you would need a hash set (O(n) space).

## *Key Points to Remember*
1. **Return value is the new size**, not the array — callers use `arr.slice(0, res)`.
2. **One-pass in-place variant**: replace `temp[res - 1]` with `arr[res - 1]` and drop the copy-back loop entirely.
3. **This is the "slow/fast pointer" pattern** — `res` is the slow pointer marking where the next unique element goes.

# **Conclusion**
Removing duplicates from a sorted array is one linear scan that compacts unique values to the front. It runs in O(n) time and can be done in O(1) space when written fully in place.
