# **Check if an Array is Sorted**

## *Introduction*
Given an array, we want to know whether its elements are in non-decreasing order (each element is less than or equal to the next one). This check is a building block for many bigger problems.

## *Idea*
1. **Walk through the array once** comparing each element with the next one.
2. **If any element is greater than the one after it**, the array is not sorted — return `false` immediately.
3. **If the loop finishes**, no violation was found — return `true`.

### Code (from articles/03.isSortedArray.js)

```JavaScript
const sortedArray = (arr) => {
  for (let i = 0; i < arr.length; i++) {
    if (arr[i] > arr[i + 1]) {
      return false;
    }
  }

  return true;
};
```

## *Analysis*
1. **Time Complexity: O(n)** — worst case scans the whole array.
2. **Space Complexity: O(1)** — no extra storage.
3. **Best case O(1)**: if the very first pair is out of order, we exit right away.

## *Key Points to Remember*
1. **Non-decreasing vs strictly increasing**: using `>` (not `>=`) means equal neighbors like `[1, 1, 2]` still count as sorted.
2. **Watch the boundary**: comparing `arr[i]` with `arr[i + 1]` only works safely because `arr[arr.length]` is `undefined` and `number > undefined` is `false`; writing `i < arr.length - 1` makes the intent clearer.
3. **Related problem**: `problems/06.sortedRotated.js` counts how many "drops" (`arr[i] > arr[i + 1]`) exist — exactly one drop plus the wrap-around condition means the array is sorted *and rotated*.

# **Conclusion**
Checking if an array is sorted is a single scan comparing adjacent elements. It takes O(n) time in the worst case, O(1) space, and the same "count the drops" idea extends to the sorted-and-rotated variant.
