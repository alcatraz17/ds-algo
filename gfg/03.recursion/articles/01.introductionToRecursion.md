# **Introduction to Recursion**

## *Introduction*
Recursion is a programming technique where a function calls itself to solve a problem. Instead of solving the whole problem at once, the function solves a small part and asks a copy of itself to solve the rest, with a slightly smaller input.

A recursive function always has two parts:
1. **Base case**: The condition that stops the recursion. It handles the smallest possible input directly, without calling the function again.
2. **Recursive case**: The part where the function calls itself with a smaller (or simpler) input, moving towards the base case.

## Simple Example

```JavaScript
function recur(num) {
  if (num < 1) {        // base case: stop when num is less than 1
    return 0;
  }

  console.log(num);
  return recur(num - 1); // recursive case: smaller input
}

recur(5); // prints 5, 4, 3, 2, 1
```

## Key Points to Remember
1. **Base case is mandatory**: Without it, the function calls itself forever and the program crashes with a stack overflow error (`RangeError: Maximum call stack size exceeded` in JavaScript).
2. **Input must shrink**: Every recursive call must move closer to the base case, otherwise the recursion never ends.
3. **Same logic, smaller problem**: The recursive case assumes the function already works for a smaller input and builds the answer for the current one on top of it.
4. **Every loop can be written recursively**: Anything a `for` or `while` loop does can also be done with recursion, and vice versa.

## When to Use Recursion?
1. **Problems with self-similar structure**: Trees, graphs, and nested data where a sub-part looks like the whole.
2. **Divide and conquer problems**: Problems that split naturally into smaller sub-problems, like merge sort or tower of Hanoi.
3. **Problems with mathematical definitions**: Factorial, Fibonacci, and sum of digits are defined recursively in math, so recursion maps to them directly.

# **Conclusion**
Recursion is a function calling itself with a smaller input until it hits a base case. The base case stops the chain of calls, and the recursive case keeps shrinking the problem. Mastering these two parts is the foundation for every recursive problem in this section.
