# **Recursion and the Call Stack**

## *Introduction*
Every time a function is called in JavaScript, the engine pushes a new **stack frame** onto the **call stack**. The frame stores the function's local variables, its parameters, and where to return after it finishes. When the function returns, its frame is removed (popped) from the stack.

Recursion is just normal function calling repeated many times — each recursive call adds a new frame on top of the previous one. The stack grows while the calls go deeper, and shrinks as the base case is reached and functions start returning.

## How It Works — Step by Step
Consider `recur(3)` from `01.plainRecursion.js`:

```JavaScript
function recur(num) {
  if (num < 1) {
    return 0;
  }

  console.log(num);
  return recur(num - 1);
}
```

The call stack grows like this (top of stack on the right):

1. `recur(3)` → stack: `[recur(3)]`
2. `recur(2)` → stack: `[recur(3), recur(2)]`
3. `recur(1)` → stack: `[recur(3), recur(2), recur(1)]`
4. `recur(0)` → base case hit, returns 0, frame popped.
5. Each waiting frame resumes, returns its value, and is popped, until the stack is empty again.

## Key Points to Remember
1. **Calls go deep first, results come back last**: The deepest call (base case) finishes first; the first call finishes last — Last In, First Out (LIFO).
2. **Work can happen on the way down or on the way up**: Code placed before the recursive call runs while going deeper (e.g. print N to 1); code placed after it runs while coming back (e.g. print 1 to N).
3. **Each frame has its own variables**: `num` in `recur(3)` and `num` in `recur(2)` are separate copies stored in separate frames.
4. **Deep recursion uses memory**: If the recursion goes too deep (e.g. `recur(100000)`), the call stack runs out of space and JavaScript throws a stack overflow error.

## Complexity of Simple Linear Recursion
- **Time Complexity: O(n)** — one frame is created per step, n steps total.
- **Space Complexity: O(n)** — the call stack holds up to n frames at the same time. An equivalent loop would use only O(1) extra space.

# **Conclusion**
The call stack is the hidden mechanism behind recursion: every recursive call pushes a frame, and every return pops one. Understanding this explains both how recursion produces results and why it costs extra memory compared to loops.
