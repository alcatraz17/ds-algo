# **Tail Recursion**

## *Introduction*
A recursive function is **tail recursive** when the recursive call is the **very last thing** the function does — there is no pending work (like an addition or a print) waiting after the call returns. Because nothing is left to do, the current stack frame is theoretically no longer needed.

## Tail Recursive vs Non-Tail Recursive
See `articles/05.tailRecursion.js` and `articles/06.naturalNumSum.js`:

```JavaScript
// NON-tail recursive: the addition happens AFTER the call returns
function sumRec(n) {
  if (n === 1) {
    return 1;
  }

  return n + sumRec(n - 1); // n must wait in memory for the result
}

// TAIL recursive: the call is the last action, result carried in 'acc'
function sumTail(n, acc = 0) {
  if (n == 0) {
    return acc;
  }

  return sumTail(n - 1, n + acc); // nothing left to do after the call
}
```

In the tail-recursive version, an **accumulator** parameter (`acc`) carries the partial result down, so the frame of the caller holds nothing that the callee still needs.

## Why Tail Recursion Matters
1. **Tail Call Optimization (TCO)**: In theory, an engine can reuse the current stack frame instead of pushing a new one, turning O(n) stack space into O(1). This prevents stack overflow on deep recursion.
2. **Same time complexity**: With or without TCO, the number of calls is the same — TCO only saves space, not time.

## Why JavaScript Engines Generally Do Not Optimize It
1. **Not implemented in practice**: Tail call optimization (called "proper tail calls") is part of the ES2015 specification, but almost no major engine ships it. V8 (Chrome, Node.js) implemented it and later **removed it**, and SpiderMonkey (Firefox) never shipped it. Only JavaScriptCore (Safari) supports it.
2. **Debugging and stack traces suffer**: Reusing frames erases the call history, so `Error.stack` and devtools would show misleading traces — a big practical cost.
3. **Never rely on it in JS**: Writing tail-recursive code does **not** protect you from `RangeError: Maximum call stack size exceeded` in Node.js or Chrome. For deep recursion, use a loop or an explicit stack instead.

## Complexity
- **Time Complexity: O(n)** — n recursive calls either way.
- **Space Complexity: O(n)** in real JavaScript engines (each call still pushes a frame). With true TCO it would be O(1).

# **Conclusion**
Tail recursion places the recursive call as the final action, using an accumulator to carry the result. While this shape enables tail call optimization in theory, mainstream JavaScript engines do not apply it, so treat tail recursion as a style and learning tool — not as a memory-saving technique in JS.
