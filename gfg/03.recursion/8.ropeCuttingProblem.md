# **Rope Cutting Problem**

## *Introduction*
**Problem**: Given a rope of length `n` and three allowed cut lengths `a`, `b`, and `c`, find the **maximum number of pieces** the rope can be cut into, using only cuts of these three lengths and using the rope completely. Return `-1` if the rope cannot be cut completely.

**Example**: `n = 5, a = 2, b = 5, c = 1` → answer is `5` (cut into five pieces of length 1).

## Recursive Idea
For a rope of length `n`, try cutting off a piece of length `a`, `b`, or `c`, then recursively find the best answer for the remaining rope. Take the maximum of the three options:

```JavaScript
function maxPieces(n, a, b, c) {
  if (n === 0) return 0;   // base case: rope fully used, 0 more pieces
  if (n < 0) return -1;    // base case: cut overshoots, invalid

  let res = Math.max(
    maxPieces(n - a, a, b, c),
    maxPieces(n - b, a, b, c),
    maxPieces(n - c, a, b, c)
  );

  if (res === -1) return -1; // no valid cut for the remainder

  return res + 1;            // this cut + best of the remainder
}

console.log(maxPieces(5, 2, 5, 1)); // 5
```

## Key Points to Remember
1. **Two base cases**: `n === 0` means success (rope fully consumed, add 0 pieces); `n < 0` means this cutting path is invalid, so return `-1`.
2. **Try all three choices**: Each call branches into up to three sub-problems — one per allowed cut length.
3. **Propagate `-1` carefully**: If all branches fail, the result stays `-1`; otherwise add 1 for the cut made at this level.
4. **Overlapping sub-problems**: The same remaining length (e.g. `n = 2`) is computed many times — this is why the plain recursive version is exponential, and why it is a classic candidate for dynamic programming later.

## Complexity
- **Time Complexity: O(3ⁿ)** — each call makes up to three recursive calls, and the recursion tree can be up to n levels deep.
- **Space Complexity: O(n)** — the maximum depth of the recursion tree is n (when cutting pieces of length 1).

# **Conclusion**
The rope cutting problem introduces **multi-branch recursion**: instead of one recursive call, each step tries three choices and keeps the best. Two base cases (`n === 0` success, `n < 0` failure) steer the search. Its O(3ⁿ) time shows exactly the kind of repeated work that dynamic programming will later eliminate.
