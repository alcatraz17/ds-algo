# **Auxiliary Space and Space Complexity**

## *Introduction*
Time is not the only resource an algorithm uses — memory matters too. **Space complexity** measures the total memory an algorithm needs, while **auxiliary space** measures only the *extra* memory used on top of the input itself.

- **Auxiliary Space** = extra/temporary space used by the algorithm (not counting the input).
- **Space Complexity** = auxiliary space + space taken by the input.

When people casually say "space complexity", they often mean auxiliary space — but it is good to know the difference.

## Why Does It Matter?
1. **Memory is limited**: An algorithm that is fast but needs gigabytes of RAM may be unusable.
2. **Trade-offs exist**: Many algorithms trade memory for speed (caching, hash tables).
3. **Recursion uses hidden space**: Every recursive call adds a frame to the call stack.

## Common Auxiliary Space Complexities

### 1. O(1) — Constant auxiliary space

```JavaScript
function sumArray(arr) {
    let sum = 0;                        // one extra variable
    for (let i = 0; i < arr.length; i++) {
        sum += arr[i];
    }
    return sum;
}
```

- Only `sum` and `i` are used, no matter how big the array is.
- **Auxiliary Space: O(1)**, Space Complexity: O(n) (the input array itself).

### 2. O(n) — Linear auxiliary space

```JavaScript
function doubleArray(arr) {
    const result = [];
    for (let i = 0; i < arr.length; i++) {
        result.push(arr[i] * 2);        // new array of size n
    }
    return result;
}
```

- A new array proportional to the input is created.
- **Auxiliary Space: O(n)**

### 3. Recursion and the call stack

```JavaScript
function factorial(n) {
    if (n <= 1) return 1;
    return n * factorial(n - 1);
}
```

- Each call waits on the stack until the deepest call returns.
- There are n nested calls, so the stack holds n frames.
- **Auxiliary Space: O(n)** — even though no array is created!

```JavaScript
function binarySearch(arr, target, low, high) {
    if (low > high) return -1;
    const mid = Math.floor((low + high) / 2);
    if (arr[mid] === target) return mid;
    if (arr[mid] > target) return binarySearch(arr, target, low, mid - 1);
    return binarySearch(arr, target, mid + 1, high);
}
```

- The recursion depth is log n (the array halves each call).
- **Auxiliary Space: O(log n)** — the iterative version of binary search needs only O(1).

## How to Analyze Space
1. **Count the extra variables and data structures**: Fixed few variables → O(1); an array or object growing with input → O(n).
2. **Add the recursion depth**: Recursive algorithms use stack space equal to the maximum call depth.
3. **Input does not count for auxiliary space**: But it does count for total space complexity.

## Key Points to Remember
1. **Auxiliary space excludes the input**; space complexity includes it.
2. **O(1) space is the goal** when possible — "in-place" algorithms need no extra memory.
3. **Recursion is not free**: Depth d recursion costs O(d) stack space.
4. **Time and space often trade off**: A hash table can turn an O(n^2) search into O(n) time at the cost of O(n) extra space.

# **Conclusion**
Auxiliary space tells you how much extra memory an algorithm needs beyond its input, and it is analyzed with the same Big O tools as time. Watch out for two common traps: data structures that grow with the input, and recursion depth silently consuming the call stack. Great algorithms are efficient in both time and space.
