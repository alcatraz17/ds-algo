# **Order of Growth**

## *Introduction*
Order of growth tells us how the running time of an algorithm increases as the input size (n) increases. It is the part of the time function that grows the fastest — we ignore constants and lower-order terms and keep only the dominant term.

For example, if an algorithm takes `3n^2 + 5n + 10` steps, its order of growth is **n^2**, because for large n the other terms barely matter.

## Common Orders of Growth (from best to worst)

| Order of Growth | Name              | Example                               |
|-----------------|-------------------|---------------------------------------|
| O(1)            | Constant          | Accessing `arr[0]`                    |
| O(log n)        | Logarithmic       | Binary search in a sorted array       |
| O(n)            | Linear            | Scanning an array once                |
| O(n log n)      | Linearithmic      | Merge sort, efficient sorting         |
| O(n^2)          | Quadratic         | Two nested loops (bubble sort)        |
| O(n^3)          | Cubic             | Three nested loops                    |
| O(2^n)          | Exponential       | Generating all subsets of a set       |
| O(n!)           | Factorial         | Generating all permutations           |

## Key Points to Remember
1. **Lower order is better**: O(log n) beats O(n), O(n) beats O(n^2), and so on for large inputs.
2. **Constants do not matter**: O(2n) and O(n) have the same order of growth — linear.
3. **Keep only the dominant term**: O(n^2 + n) is simply O(n^2).
4. **Small inputs can be misleading**: For tiny n, an O(n^2) algorithm may run faster than an O(n log n) one, but the trend always wins as n grows.

## How Fast Do They Grow?

For `n = 1000`:

- O(1) → 1 step
- O(log n) → about 10 steps
- O(n) → 1,000 steps
- O(n log n) → about 10,000 steps
- O(n^2) → 1,000,000 steps
- O(2^n) → more steps than atoms in the universe

```JavaScript
// O(1) - constant
const first = (arr) => arr[0];

// O(n) - linear
const sum = (arr) => arr.reduce((total, x) => total + x, 0);

// O(n^2) - quadratic
const printPairs = (arr) => {
    for (let i = 0; i < arr.length; i++) {
        for (let j = 0; j < arr.length; j++) {
            console.log(arr[i], arr[j]);
        }
    }
};
```

# **Conclusion**
Order of growth is the simplest way to compare algorithms: drop the constants, keep the fastest-growing term, and see which category it falls into. Algorithms with a lower order of growth scale better, so always aim for the lowest order you can achieve for the problem.
