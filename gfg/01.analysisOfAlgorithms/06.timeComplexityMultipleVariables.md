# **Time Complexity with Multiple Variables**

## *Introduction*
So far we measured everything in terms of a single input size (n). But many problems have more than one input, and the running time can depend on each of them independently. In that case we must express the complexity using **all** the relevant variables — we cannot just merge them into one n.

## Why One Variable Is Not Always Enough

Consider a function that takes two arrays of different sizes. Their lengths are independent inputs, so we give them separate names, commonly `n` and `m`.

## Common Patterns

### 1. Sequential loops over different inputs — O(n + m)

```JavaScript
function printBoth(arrA, arrB) {
    for (let i = 0; i < arrA.length; i++) {      // n times
        console.log(arrA[i]);
    }
    for (let j = 0; j < arrB.length; j++) {      // m times
        console.log(arrB[j]);
    }
}
```

- Total work is n + m, and neither term dominates the other in general.
- **Time Complexity: O(n + m)** — you can NOT simplify this to O(n), because n and m are unrelated.

### 2. Nested loops over different inputs — O(n * m)

```JavaScript
function printCrossPairs(arrA, arrB) {
    for (let i = 0; i < arrA.length; i++) {      // n times
        for (let j = 0; j < arrB.length; j++) {  // m times
            console.log(arrA[i], arrB[j]);       // n * m times
        }
    }
}
```

- **Time Complexity: O(n * m)** — common when comparing every element of one collection with every element of another.

### 3. A different variable altogether — O(k) or O(log k)

Sometimes the input size is not an array length but a number's value or magnitude.

```JavaScript
function countUpTo(k) {
    for (let i = 1; i <= k; i++) {
        console.log(i);            // runs k times
    }
}
```

- **Time Complexity: O(k)** — linear in the *value* of k, not in the number of inputs.

```JavaScript
function gcd(a, b) {
    while (b !== 0) {
        [a, b] = [b, a % b];
    }
    return a;
}
```

- Each step shrinks the numbers quickly; the loop runs O(log(min(a, b))) times.
- **Time Complexity: O(log(min(a, b)))** — the complexity depends on the *values*, not on an input count.

### 4. Matrix-style inputs — O(rows * cols)

```JavaScript
function printMatrix(matrix) {
    for (let r = 0; r < matrix.length; r++) {          // R rows
        for (let c = 0; c < matrix[r].length; c++) {   // C columns
            console.log(matrix[r][c]);
        }
    }
}
```

- **Time Complexity: O(R * C)** — for a square matrix this becomes the familiar O(n^2).

## Key Points to Remember
1. **Name every independent input**: Use n, m, k, R, C — one variable per independent size.
2. **Do not merge variables**: O(n + m) is not O(n) unless you know m <= n for sure.
3. **Value vs. count**: A loop bounded by a number's *value* (like O(k)) can be huge even for a single input — watch out for this with numeric algorithms.
4. **Nested over different inputs multiplies**: O(n) over one array inside O(m) over another gives O(n * m).

# **Conclusion**
When a function has multiple independent inputs, the time complexity must mention all of them — O(n + m), O(n * m), O(R * C), or O(log(min(a, b))). Always identify what each loop's bound actually depends on (a length, a value, a row count) before writing down the final complexity.
