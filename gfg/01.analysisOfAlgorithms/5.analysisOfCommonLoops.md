# **Analysis of Common Loops**

## *Introduction*
Most of an algorithm's running time is spent inside loops, so analyzing loops is the core skill of time complexity analysis. The rule is simple: count how many times the loop body runs, and express it in terms of the input size (n).

## 1. Single Loops

A loop that runs a fixed number of times proportional to n is **O(n)**.

```JavaScript
function printItems(arr) {
    for (let i = 0; i < arr.length; i++) {
        console.log(arr[i]);       // runs n times
    }
}
```

- The body runs n times, each iteration is constant work.
- **Time Complexity: O(n)**

A loop with a constant number of iterations does not depend on n at all:

```JavaScript
function printFirstHundred(arr) {
    for (let i = 0; i < 100; i++) {
        console.log(arr[i]);       // runs 100 times, always
    }
}
```

- **Time Complexity: O(1)**

## 2. Nested Loops

When a loop sits inside another loop, the total work is the product of the iterations.

```JavaScript
function printAllPairs(arr) {
    for (let i = 0; i < arr.length; i++) {        // n times
        for (let j = 0; j < arr.length; j++) {    // n times
            console.log(arr[i], arr[j]);          // n * n times
        }
    }
}
```

- **Time Complexity: O(n^2)**

A common variation where the inner loop depends on the outer variable:

```JavaScript
function printUniquePairs(arr) {
    for (let i = 0; i < arr.length; i++) {
        for (let j = i + 1; j < arr.length; j++) {
            console.log(arr[i], arr[j]);
        }
    }
}
```

- The body runs `n + (n-1) + ... + 1 = n(n-1)/2` times.
- Dropping constants and lower-order terms, it is still **O(n^2)**.

Sequential (not nested) loops add up instead of multiplying, so two separate O(n) loops are still O(n).

## 3. Logarithmic Loops

When the loop variable is multiplied or divided each iteration (instead of adding), the loop runs only log n times.

```JavaScript
function halveUntilOne(n) {
    for (let i = n; i >= 1; i = Math.floor(i / 2)) {
        console.log(i);            // runs log2(n) times
    }
}
```

- n is cut in half each step, so it takes about log2(n) steps to reach 1.
- **Time Complexity: O(log n)** — this is the pattern behind binary search.

The same applies when the variable doubles: `for (let i = 1; i < n; i *= 2)` is also O(log n).

## 4. While Loops

Analyze a while loop exactly like a for loop — ask how many times the body runs.

```JavaScript
function countDigits(n) {
    let count = 0;
    while (n > 0) {
        n = Math.floor(n / 10);    // divide by 10 each step
        count++;
    }
    return count;
}
```

- n loses one digit per iteration, so the loop runs about log10(n) times.
- **Time Complexity: O(log n)**

```JavaScript
function findElement(arr, target) {
    let i = 0;
    while (i < arr.length && arr[i] !== target) {
        i++;                       // at most n steps
    }
    return i < arr.length ? i : -1;
}
```

- In the worst case (target missing) it checks every element.
- **Time Complexity: O(n)** — same as the for-loop version of linear search.

## Key Points to Remember
1. **Count iterations**: Time complexity of a loop = number of times the body runs.
2. **Nested loops multiply**: An O(n) loop inside an O(n) loop gives O(n^2).
3. **Sequential loops add**: Two O(n) loops one after another are O(n + n) = O(n).
4. **Halving or doubling means logarithmic**: If the counter jumps by a factor each step, think O(log n).

# **Conclusion**
Loop analysis comes down to one question: how many times does the loop body execute? Single loops are usually linear, nested loops multiply into quadratic or worse, and loops that shrink the problem by a factor each step are logarithmic. Master these four patterns and most time complexity questions become straightforward.
