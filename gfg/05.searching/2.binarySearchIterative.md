# **Binary Search (Iterative)**

## *Introduction*
Binary search is a fast searching technique that works on **sorted** arrays. Instead of checking elements one by one, it compares the target with the middle element and throws away half of the remaining array in every step.

## Why Does Binary Search Need Sorted Input?
1. **The decision depends on order**: When `arr[mid] > element`, we know the element can only be on the left half **only because** the array is sorted. In an unsorted array, the element could be anywhere, so discarding half would be wrong.
2. **Sorted order is the guarantee**: Binary search trades the flexibility of linear search for speed, and sorted data is the price we pay.

## How It Works
1. **Keep two pointers**: `start` at 0 and `end` at the last index.
2. **Find the middle**: `mid = Math.floor((start + end) / 2)`.
3. **Compare with the target**:
   - If `arr[mid]` equals the target, return `mid`.
   - If `arr[mid]` is greater, the target must be on the left, so `end = mid - 1`.
   - If `arr[mid]` is smaller, the target must be on the right, so `start = mid + 1`.
4. **Repeat until** `start > end`, then return -1 (not found).

```javascript
function binarySearch(arr, element) {
  let start = 0;
  let end = arr.length - 1;

  while (start <= end) {
    let mid = Math.floor((start + end) / 2);
    if (arr[mid] === element) {
      return mid;
    } else if (arr[mid] > element) {
      end = mid - 1;
    } else {
      start = mid + 1;
    }
  }
  return -1;
}

console.log(binarySearch([1, 2, 3, 4, 5], 3)); // 2
```

## Complexity Analysis
1. **Time complexity O(log n)**: The search space halves in every step. For n = 1000000, only about 20 comparisons are needed.
2. **Best case O(1)**: The middle element is the target.
3. **Space complexity O(1)**: Only a few variables are used, no extra memory.
4. **Overflow note**: In languages like C/C++/Java, use `mid = start + (end - start) / 2` to avoid integer overflow. In JavaScript, numbers do not overflow for realistic array sizes, so `(start + end) / 2` is safe.

# **Conclusion**
Iterative binary search runs in O(log n) time and O(1) space, making it far better than linear search for sorted arrays. The key idea is discarding half of the search space at every step, which only works because the array is sorted.
