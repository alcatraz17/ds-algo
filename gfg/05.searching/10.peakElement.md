# **Peak Element**

## *Introduction*
A peak element is an element that is greater than (or equal to) its neighbors. Example: in `[5, 10, 20, 15, 7]`, the element 20 is a peak. For edge elements, only one neighbor exists — the first element is a peak if it is ≥ the second, and the last is a peak if it is ≥ the second-last. Any one valid peak can be returned.

## The Key Idea
1. **A peak always exists**: If the array keeps rising toward the right, the last element is a peak; if it keeps falling, the first element is a peak; otherwise it rises and falls somewhere, creating a peak in the middle.
2. **Follow the uphill direction**: If `arr[mid] < arr[mid + 1]`, the array is rising to the right, so a peak must exist on the right side. If `arr[mid] < arr[mid - 1]`, a peak must exist on the left side.

```javascript
function findPeak(arr) {
  let low = 0;
  let high = arr.length - 1;

  while (low <= high) {
    let mid = Math.floor((low + high) / 2);
    let left = mid === 0 ? -Infinity : arr[mid - 1];
    let right = mid === arr.length - 1 ? -Infinity : arr[mid + 1];

    if (arr[mid] >= left && arr[mid] >= right) {
      return mid; // peak found
    } else if (arr[mid] < right) {
      low = mid + 1; // peak must be on the right
    } else {
      high = mid - 1; // peak must be on the left
    }
  }
  return -1;
}

console.log(findPeak([5, 10, 20, 15, 7])); // 2
```

## Key Points to Remember
1. **The array need not be sorted**: This is binary search used on an **unsorted** array — the "climb uphill" logic replaces the sorted-order check.
2. **Edge elements**: Treat the missing neighbor as -Infinity (or handle `mid === 0` and `mid === n - 1` explicitly).
3. **Time complexity O(log n)**: Half the array is discarded each step.
4. **Space complexity O(1)**: Only pointers are used.

## Naive Approach
Scan the array and return the first element that is ≥ both neighbors. This takes O(n) time.

# **Conclusion**
A peak element always exists, and moving toward the bigger neighbor guarantees reaching one. This lets binary search find a peak in O(log n) time and O(1) space, even though the array is not sorted.
