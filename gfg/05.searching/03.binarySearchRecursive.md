# **Binary Search (Recursive)**

## *Introduction*
Binary search can also be written recursively. The idea is exactly the same as the iterative version — compare with the middle and discard half — but instead of a loop, the function calls itself with a smaller range.

## How It Works
1. **Base case**: If `start > end`, the element is not present, return -1.
2. **Find the middle**: `mid = Math.floor((start + end) / 2)`.
3. **Three cases**:
   - `arr[mid] === element`: return `mid`.
   - `arr[mid] > element`: search the left half recursively (`start` to `mid - 1`).
   - `arr[mid] < element`: search the right half recursively (`mid + 1` to `end`).

```javascript
function binSearch(arr, start, end, element) {
  if (start > end) return -1;

  const mid = Math.floor((start + end) / 2);

  if (arr[mid] === element) {
    return mid;
  } else if (arr[mid] > element) {
    return binSearch(arr, start, mid - 1, element);
  } else {
    return binSearch(arr, mid + 1, end, element);
  }
}

console.log(binSearch([1, 2, 3, 4, 5], 0, 4, 2)); // 1
```
See `articles/02.binarySearchRec.js`. (Note: the file passes `end = 5`; passing `arr.length - 1 = 4` is the correct bound.)

## Complexity Analysis
1. **Time complexity O(log n)**: Same as iterative — the search space halves with each call. Recurrence: `T(n) = T(n/2) + O(1)`.
2. **Space complexity O(log n)**: Each recursive call adds a frame on the call stack, and there are about log n nested calls. This is the main difference from the iterative version, which uses O(1) space.
3. **Best case O(1)**: Target is the very first middle element.

## Iterative vs Recursive
1. **Time**: Both are O(log n).
2. **Space**: Iterative is O(1); recursive is O(log n) due to the call stack.
3. **Readability**: Recursive code is shorter and mirrors the divide-and-conquer idea, but the iterative version is preferred in practice because it avoids stack overhead.

# **Conclusion**
Recursive binary search is O(log n) in time but O(log n) in space because of the call stack. It is a clean way to express the algorithm, but the iterative version is more memory efficient for the same result.
