# **Majority Element**

## *Introduction*
A majority element is an element that appears **strictly more than n/2** times in an array of size n. Example: in `[1, 1, 2, 1, 3, 5, 1]`, the answer is 1 (it appears 4 out of 7 times). If no such element exists, return -1.

## Key Points to Remember
1. **At most one majority element can exist**: Two different elements cannot both appear more than half the time.
2. **In a sorted array, the majority element must occupy the middle index**: More than n/2 copies of the same value cannot all fit without covering index `⌊n/2⌋`.

## Approach 1: Binary Search on a Sorted Array — O(log n)
If the array is **sorted**, candidate = `arr[Math.floor(n / 2)]`. Then verify it really is a majority by counting its occurrences with the first/last occurrence binary searches:

```javascript
function majoritySorted(arr) {
  const n = arr.length;
  const candidate = arr[Math.floor(n / 2)];

  const first = firstOccurrence(arr, candidate); // O(log n)
  const last = lastOccurrence(arr, candidate);   // O(log n)
  const count = first === -1 ? 0 : last - first + 1;

  return count > n / 2 ? candidate : -1;
}
```
1. **Time complexity O(log n)**: Two binary searches.
2. **Space complexity O(1)**: No extra memory.
3. **Limitation**: Only works on sorted arrays.

## Approach 2: Boyer-Moore Voting Algorithm — O(n) for Any Array
For an **unsorted** array (the usual interview version), use Boyer-Moore voting, which the user implemented in `problems/08.majorityElement.js`:
1. **Phase 1 — find a candidate**: Keep a `candidate` and a `count`. When `count` is 0, pick the current element as candidate. Increment `count` when the element matches the candidate, decrement otherwise. If a majority element exists, it survives this "canceling out".
2. **Phase 2 — verify**: Count the candidate's occurrences in a second pass to confirm it is > n/2 (Phase 1 alone can return a wrong candidate when no majority exists).
3. **Time complexity O(n)**, **space complexity O(1)** — no hash map needed.

```javascript
function majorityElement(arr) {
  let candidate = 0, count = 0;

  for (const num of arr) {
    if (count === 0) { candidate = num; count = 1; }
    else if (num === candidate) count++;
    else count--;
  }

  count = arr.filter(num => num === candidate).length;
  return count > arr.length / 2 ? candidate : -1;
}
```

## Comparison
1. **Hash map counting**: O(n) time but O(n) space (see the commented-out solution in `problems/08.majorityElement.js`).
2. **Binary search (sorted only)**: O(log n) time, O(1) space.
3. **Boyer-Moore (any array)**: O(n) time, O(1) space — the general best answer.

# **Conclusion**
For a sorted array, the majority element sits at the middle index and can be verified with two binary searches in O(log n). For a general array, Boyer-Moore voting finds it in O(n) time and O(1) space. Related: `problems/09.majorityNDividedKElement.js` generalizes the idea to elements appearing more than n/k times.
