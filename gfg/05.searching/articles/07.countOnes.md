# **Count 1s in a Sorted Binary Array**

## *Introduction*
Given a sorted binary array that looks like `[1, 1, 1, 1, 0, 0, 0]` (all 1s first, then all 0s), count how many 1s it contains.

## The Key Idea
1. **Count of 1s = index of the first 0**: Since all 1s come before all 0s, the position where the first 0 appears equals the number of 1s. If no 0 exists, the whole array is 1s, so the count is `arr.length`.
2. **Binary search for the boundary**: The transition point from 1 to 0 can be found in O(log n) instead of scanning the array.

## Approach 1: Find the First 0
```javascript
function countOnes(arr) {
  let left = 0;
  let right = arr.length - 1;
  let firstZero = arr.length; // default: no 0 found

  while (left <= right) {
    let mid = Math.floor((left + right) / 2);

    if (arr[mid] === 0) {
      firstZero = mid;  // possible answer, but check further left
      right = mid - 1;
    } else {
      left = mid + 1;   // arr[mid] is 1, move right
    }
  }
  return firstZero;
}

console.log(countOnes([1, 1, 1, 1, 0, 0, 0, 0, 0])); // 4
```

## Key Points to Remember
1. **This is a boundary search**: Just like first occurrence, we do not stop at the first 0 we find — we keep moving left to be sure it is the earliest one.
2. **Edge case — no zeros**: If the array is all 1s, return `arr.length`.
3. **Edge case — no ones**: If the array is all 0s, the first 0 is at index 0, so the count is 0.
4. **Time complexity O(log n)**: Binary search halves the range each step.
5. **Space complexity O(1)**: Only pointers are used.

## Naive Approach
Count 1s with one pass over the array in O(n) time. Fine for small arrays, but binary search is O(log n).

# **Conclusion**
Counting 1s in a sorted binary array reduces to finding the boundary between 1s and 0s — either the first 0 or the last 1. Binary search does it in O(log n) time and O(1) space.
