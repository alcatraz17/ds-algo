# **Search in an Infinite-Sized Array (Unbounded Binary Search)**

## *Introduction*
Suppose a sorted array is conceptually "infinite" — we do not know its length, or reading beyond the end is not allowed. We cannot set `high = arr.length - 1` because we do not know the length. The task is still to find a target efficiently.

## The Key Idea
1. **First find a range, then binary search**: We cannot binary search without bounds, so we first locate a window that contains the target, then run normal binary search inside it.
2. **Exponential (galloping) search for the bound**: Check indexes 1, 2, 4, 8, 16, ... — doubling each time — until `arr[i] >= target`. The target (if present) must lie between `i/2` and `i`.

```javascript
function binarySearch(arr, target, low, high) {
  while (low <= high) {
    let mid = Math.floor((low + high) / 2);
    if (arr[mid] === target) return mid;
    if (arr[mid] > target) high = mid - 1;
    else low = mid + 1;
  }
  return -1;
}

function searchInfinite(arr, target) {
  if (arr[0] === target) return 0;

  let i = 1;
  while (arr[i] < target) {
    i = i * 2; // double the jump
  }
  if (arr[i] === target) return i;

  // target lies in (i/2, i)
  return binarySearch(arr, target, Math.floor(i / 2) + 1, i - 1);
}
```

## Complexity Analysis
Let the target be at position `p` (or the first element greater than it is at position `p`).
1. **Finding the bound**: Doubling reaches `p` in about log(p) steps.
2. **Binary search in the range**: The range `[p/2, p]` has size at most p/2, so this also takes O(log p).
3. **Total time complexity O(log p)**: Where p is the position of the target — not related to the total array size, which we never even know.
4. **Space complexity O(1)**: Only pointers are used.

## Key Points to Remember
1. **Why doubling, not fixed steps?**: Stepping one by one would be O(p). Doubling makes finding the bound logarithmic.
2. **Also called**: Exponential search or unbounded binary search.
3. **Useful for**: Very large or streaming data where the end is unknown or expensive to reach.

# **Conclusion**
When the array size is unknown, first find a bounding range by doubling the index (1, 2, 4, 8, ...), then binary search inside that range. The total time is O(log p), where p is the target's position, and space is O(1).
