# **Index of First Occurrence**

## *Introduction*
In a sorted array with duplicates, plain binary search returns **some** index of the target, not necessarily the first one. The "first occurrence" problem asks for the **leftmost** index where the target appears. Example: in `[1, 2, 3, 4, 5, 6, 7, 7, 7, 7, 7]`, the first occurrence of 7 is index 6.

## How It Works
1. **Run a normal binary search** until `arr[mid] === element`.
2. **Check if mid is the first occurrence**: It is the first if `mid === 0` (target at the very start) **or** `arr[mid - 1] !== element` (previous element is different). Return `mid`.
3. **Otherwise keep looking left**: Set `high = mid - 1`, because an earlier occurrence must exist on the left.
4. **If not found**, return -1.

```javascript
function firstOccurrence(arr, element) {
  let low = 0;
  let high = arr.length - 1;

  while (low <= high) {
    let mid = Math.floor((low + high) / 2);

    if (arr[mid] === element) {
      if (mid === 0 || arr[mid - 1] !== element) {
        return mid;
      } else {
        high = mid - 1; // an earlier 7 exists on the left
      }
    } else if (arr[mid] < element) {
      low = mid + 1;
    } else {
      high = mid - 1;
    }
  }
  return -1;
}

console.log(firstOccurrence([1, 2, 3, 4, 5, 6, 7, 7, 7, 7, 7], 7)); // 6
```
See `03.firstOccurrence.js`. A variation that records the match and keeps moving left is in `../problems/02.findLeftmostIndex.js`.

## Key Points to Remember
1. **Why not stop at the first match?**: The match may be a duplicate in the middle of the run; the real first occurrence can still be further left.
2. **The neighbor check**: Comparing with `arr[mid - 1]` is what turns plain binary search into "first occurrence" search.
3. **Time complexity O(log n)**: We still discard half the array each step.
4. **Space complexity O(1)** for the iterative version (O(log n) if written recursively).

## Naive Approach
Scanning from the left with a linear search also finds the first occurrence, but takes O(n) time. Binary search improves it to O(log n).

# **Conclusion**
Finding the first occurrence is a small twist on binary search: when you find the target, check the previous element — if it is the same, keep searching left. The cost stays O(log n) time and O(1) space.
