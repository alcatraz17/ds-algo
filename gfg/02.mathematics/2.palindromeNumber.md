# **Palindrome Number**

## *Introduction*
A palindrome number reads the same forwards and backwards. For example, 121 and 1331 are palindromes, but 1213 is not. The standard way to check is to reverse the number and compare it with the original.

## Approach: Reverse the Number
Peel off digits from the end one by one and build the reversed number. Then compare. See `articles/2.palindrome.js`.

```JavaScript
const isPalindrome = (num) => {
  let number = num;
  let reverse = 0;

  while (number > 0) {
    let mod = number % 10;
    reverse = reverse * 10 + mod;
    number = Math.floor(number / 10);
  }

  return reverse === num;
};
```

### How it works (num = 121)
1. Take the last digit with `% 10`: 1. Reverse becomes 1.
2. Next digit: 2. Reverse becomes 12.
3. Next digit: 1. Reverse becomes 121.
4. 121 === 121, so it is a palindrome.

- **Time Complexity**: O(d) where d is the number of digits, i.e. O(log10(n)).
- **Space Complexity**: O(1).

## *Key Points to Remember*
1. **`num % 10` gives the last digit**, `Math.floor(num / 10)` removes it.
2. **Build the reverse** with `reverse = reverse * 10 + lastDigit`.
3. **Keep a copy of the original number**, because the loop destroys it.

# **Conclusion**
The palindrome check is a direct application of digit extraction: reverse the number using modulo and division, then compare with the original. It runs in O(log n) time with constant extra space.
