# **Modular Arithmetic Basics**

## *Introduction*
Modular arithmetic is arithmetic with a wrap-around: `a % m` gives the remainder of a divided by m (0 to m − 1). It keeps huge numbers small, which is why competitive programming answers are often requested "modulo 10^9 + 7".

## Basic Identities
You can take the modulo at any intermediate step — the final result does not change:

1. **Addition**: `(a + b) % m = ((a % m) + (b % m)) % m` — see `problems/08.additionUnderModulo.js`.
2. **Multiplication**: `(a × b) % m = ((a % m) × (b % m)) % m` — see `problems/09.multiplicationUnderModulo.js`.
3. **Subtraction**: `(a − b) % m = ((a % m) − (b % m) + m) % m` — the `+ m` avoids negative results.

```JavaScript
const addMod = (a, b, m) => ((a % m) + (b % m)) % m;
const mulMod = (a, b, m) => ((a % m) * (b % m)) % m;
```

- **Time Complexity**: O(1) each.
- **Space Complexity**: O(1).

## Why modulo after every step?
Applying `% m` inside loops (e.g. in factorial or power) prevents the intermediate values from overflowing, while the final answer stays correct.

## Modular Inverse
The modular inverse of a modulo m is a number x such that **(a × x) % m = 1**. It plays the role of division: instead of dividing by a, you multiply by its inverse. The inverse exists **only if gcd(a, m) = 1** (a and m are coprime).

It can be found with the **Extended Euclidean Algorithm**, which finds x, y such that `a×x + m×y = gcd(a, m)`. If gcd is 1, x is the inverse. See `problems/10.moduloInverse.js`.

```JavaScript
function modInverse(n, m) {
  let a = n, b = m;
  let x0 = 1, x1 = 0;
  while (b > 0) {
    let q = Math.floor(a / b);
    [a, b] = [b, a % b];
    [x0, x1] = [x1, x0 - q * x1];
  }
  if (a !== 1) return -1;        // inverse does not exist
  return ((x0 % m) + m) % m;     // normalize to positive
}
```

- **Time Complexity**: O(log(min(a, m))) — same as the Euclidean algorithm.
- **Space Complexity**: O(1).

### Fermat's Little Theorem (bonus)
If m is prime, `a^(m−1) % m = 1`, so the inverse of a is `a^(m−2) % m` — computable with binary exponentiation in O(log m).

## *Key Points to Remember*
1. **Take modulo at every step** for addition, multiplication, and exponentiation.
2. **Add m before final modulo in subtraction** to keep results non-negative.
3. **Division is not direct under modulo** — multiply by the modular inverse instead.
4. **The inverse exists only when gcd(a, m) = 1**.

# **Conclusion**
Modular arithmetic keeps computations bounded using simple identities for +, −, and ×, while division is handled through the modular inverse found via the Extended Euclidean Algorithm (or Fermat's theorem for prime moduli). These tools appear constantly in number-theory and counting problems.
